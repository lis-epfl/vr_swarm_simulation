# Agent File Index

Architecture, the shared-memory contract, and the cross-cutting invariants live in
[CLAUDE.md](CLAUDE.md) (auto-loaded). This file is just a map of *where things live* — read the
actual file for behavior, since these pointers are intentionally not kept in lock-step with the code.

## Swarm flight control (per-drone, Unity)

Chain: **SwarmManager (config) → SwarmAlgorithm (dispatch) → flocking force → VelocityControl**;
yaw is separate via AttitudeAlgorithm. Every scene spawns the same `Assets/Prefabs/DroneReduced.prefab`,
so per-scene tuning belongs on the scene's `SwarmManager`.

- [SwarmManager.cs](Assets/Scripts/swarm/SwarmManager.cs) — singleton holding all swarm/attitude params; fires `swarmParamsChanged` on edit; selects active algorithms. The one per-scene owner of the tuning: the Olfati-Saber gains, the altitude ceiling (`maxHeightAboveTerrain`, 0 = off), the look-direction gap fill (`fillLookDirectionGap`), `gimbalPitch`.
- [SwarmAlgorithm.cs](Assets/Scripts/swarm/SwarmAlgorithm.cs) — per-drone dispatcher; writes a world-frame accel to `VelocityControl.swarmAcceleration` each `FixedUpdate` and pushes the params update (ceiling included) into each drone.
- [OlfatiSaber.cs](Assets/Scripts/swarm/OlfatiSaber.cs) — main flocking law (consensus + cohesion + close-range closing damper + obstacle avoidance + hollow core, its velocity match relative to the swarm). An obstacle is any collider on layer `Obstacle`, modelled as the circumradius cylinder of its bounds. `Reynolds` is the simpler alternative.
- [AttitudeAlgorithm.cs](Assets/Scripts/swarm/AttitudeAlgorithm.cs) — per-drone yaw/heading, the analogue of the PC's `heading_hold_rate` (the FC half is in `VelocityControl`); sets `BoundaryEstimate` (convex-hull edge flag); `UpdateLookGapShift` turns the two hull drones bracketing the body yaw towards it (`GLOBAL_CONVEXHULL` only, off by default); hands a lone drone the yaw stick.
- [SwarmRegistry.cs](Assets/Scripts/swarm/SwarmRegistry.cs) — cache of each drone's per-tick components keyed by its root, so the per-neighbour hot loops don't `Find`/`GetComponent`; `TryGetLoneDrone` (exactly one alive) is the lone-drone detection `AttitudeAlgorithm`, `PyUniSharingFast` and `ScreenSpawn` share.
- [Editor/DroneFrustumGizmos.cs](Assets/Scripts/swarm/Editor/DroneFrustumGizmos.cs) — Scene-view FPV frustum per drone whatever is selected (`[DrawGizmo]` on `FPVCameraScript`, no scene wiring): green on the hull, red interior. Settings in Preferences > Swarm, toggle in Tools > Swarm.
- [ObstacleCylinderGizmos.cs](Assets/Scripts/swarm/ObstacleCylinderGizmos.cs) — Scene-view view of the cylinder obstacle model (`[ExecuteAlways]`, so it draws in edit mode); `drawBounds` shows the phantom shell between a facade and its cylinder.
- [SwarmPlaneController.cs](Assets/Scripts/swarm/SwarmPlaneController.cs) — owns the swarming plane and the `V` toggle into vertical-wall mode; publishes the pilot-steered shared target heading (`TargetYaw`), the centroid plane offset (`PlaneOrigin`) and the wall's latched reference altitude (no leader drone; clamped to the ceiling), the plane axes (`GetPlaneAxes`) and `SwarmMeanVelocity` for the hollow core. Also resolves the display configuration (`RefreshDisplayConfiguration` / `TryResolveDisplayConfiguration` / `StyleForConfiguration`: wall ⇒ `PLANAR` + `FORMATION_WALL`, nadir ⇒ `PLANAR` + `FORMATION_MAP`, looking out ⇒ `STABSTITCH` + `OUTER_CIRCLE`) for sim and real feeds alike.
- [VelocityControl.cs](Assets/Scripts/VelocityControl/VelocityControl.cs) — low-level controller (tilt/yaw/height loops, circular clamps); the FC-side heading hold (`headingSetpoint`, `headingHoldKp`, back-calculated, with yaw drag compensation); clamps the height setpoint to the terrain ceiling and the `MinHeight` floor; reads limits from a `FlightProfile`.
- [StateFinder.cs](Assets/Scripts/VelocityControl/StateFinder.cs) — per-drone state estimate with IMU/GPS-style noise (the flight controller's input; the stitcher's pose error is `StitchPoseSource`'s, separately).
- [DroneHealthMonitor.cs](Assets/Scripts/VelocityControl/DroneHealthMonitor.cs) — the loss rules (crash tilt, `TooFarFromSwarm`) and parking/unparking a lost drone.
- [FlightProfile.cs](Assets/Scripts/VelocityControl/FlightProfile.cs) — ScriptableObject of airframe/controller limits; its defaults match `VelocityControl`'s, so a default profile changes nothing.
- [SwarmSpawn.cs](Assets/Scripts/swarm/SwarmSpawn.cs) — spawns the drone grid, wires the `swarm` list into each drone, merges each drone's body (`combineDroneBodies`), plus reset/reposition/health helpers.

## Pilot input and launch

- [UDPReceiverManager.cs](Assets/Scripts/Control/UDPReceiverManager.cs) — the RC joystick over UDP (port 5055, from `rcjoy bridge --profile sim`). Runs before `InputManager` (execution order −200), drains every queued datagram each frame and acts on the newest; `IsStale` after `staleAfterSeconds` (0.5 s) with no packet; `MarkPresses` turns the bridge's cumulative C2 count into presses for the recorder's identify.
- [InputManager.cs](Assets/Scripts/Control/InputManager.cs) — keyboard / joystick / any, and the command frame (`Body`, `World`, `VR` = the pilot's body heading). On a stale joystick it flies neutral sticks but keeps spread, s1 and gimbal pitch; in `ANY` the keyboard takes over.
- [launch_sim_scripts.ps1](launch_sim_scripts.ps1) — one Windows Terminal: `StitcherThreading.py` in the `stitching` env and the `rcjoy bridge`; turns Oculus ASW off on every launch (`-Asw Auto` / `Keep`), and `-RcIP` when the RC is not found.

## VR display & camera capture (Unity ↔ Python bridge)

- [PyUniSharingFast.cs](Assets/Scripts/ImageStitching/PyUniSharingFast.cs) — captures the selected feeds → `BlockSharedMemory` (the body-yaw-relative left/centre/right boundary triplet for `STABSTITCH`, every plane-facing drone in `PLANAR`, each block carrying the pose its pixels were rendered from), writes metadata, the body yaw (`bodyYaw`, slaved to the plane in wall mode and to a lone drone's commanded heading) and the producer heartbeat, resolves and publishes the scene plane, the planar centre drone and the planar standoff (`ResolvePlanarStandoff`: the PC's value via `ImageSharing` or the inspector fallback), reads the panorama (uploaded only when its sequence number changes), renders the curved screen, and drives the quality fallback and `HideStitchedFeeds`. Owns the block section's fixed geometry (`blockSlotCapacity` × `blockSlotStride`, created once in `Start` and never resized — a named section cannot be); readbacks are converted straight into their blocks (`ConvertReadback`, `bridge.inPlaceReadback`) and PLANAR's renders are spread over frames (`bridge.maxCapturesPerFrame`). Section names take `STITCH_SHM_SUFFIX`.
- [StitchPoseSource.cs](Assets/Scripts/ImageStitching/StitchPoseSource.cs) — injects drifting GNSS-magnitude error (Ornstein–Uhlenbeck + common-mode + yaw bias) into the published camera poses. Deliberately separate from `StateFinder`, whose noise feeds the flight controller.
- [ImageSharing.cs](Assets/Scripts/dji/ImageSharing.cs) — real-drone mode (DJIScene): reads all live feeds from `DroneFeedSharedMemory` (written by the DJI_Swarm repo's `image_stream_feed.py`), shows them on the feed screens (`ScreenSpawn.UpdateRealDroneFeed` pushes pose and freshness, so every screen style works off real feeds), and re-publishes the selected views into `BlockSharedMemory` for the stitcher — 3 by body yaw for `STABSTITCH`, every fresh drone for `PLANAR`, with no slot-count knob to set. Passes each frame's camera pose through from one map to the other without computing it. Reads the feed map's seqlocked standoff trailer (`FeedStandoff*` statics, heartbeat-gated) and publishes `LiveFeed*` for the display-configuration resolver. Mirrors `PyUniSharingFast`'s block-section constants, because both components create that same named section.
- [FPVCameraScript.cs](Assets/Scripts/Camera/FPVCameraScript.cs) — drives each drone's FPV camera as a stabilised DJI-style gimbal (roll 0, swarm-wide pitch, yaw locked to the drone) and hides the owning drone's body for its own pass. Also owns `EnsureRenderedThisFrame`, the once-per-frame render gate both `ScreenSpawn`'s feed refresh and `PyUniSharingFast`'s stitch capture go through, so a drone that is displayed *and* stitched is drawn once. That gate keeps the render record (time, and the pose the pixels were drawn from) and the swarm-wide render counters (`RendersThisFrame`, `TotalRenders`) the feed leveling and `_perf.csv` read. `NadirPitch` is the gimbal threshold for the nadir configuration.
- [FpvCameraFov.cs](Assets/Scripts/Camera/FpvCameraFov.cs) — the FPV camera's field of view in one place (82.1° diagonal → 74.4° × 46.2° at the 16:9 feed): `ScreenSpawn` sets the cameras from it and the bench's look-gap metrics use it. Mirrored by `citysim/camera.py`, which `analyse.py` reads; change the two together.
- [DroneBodyCombiner.cs](Assets/Scripts/Camera/DroneBodyCombiner.cs) — added by `SwarmSpawn` to each drone at spawn (`combineDroneBodies`): merges the DJI model's 96 rigid body renderers into one per material (mirrored parts on a second, scale -1 child), leaving the four propellers alone, so another drone in an FPV view costs ~11 draw calls instead of ~96.
- [InterfaceManager.cs](Assets/Scripts/Interface/InterfaceManager.cs) — the single source of truth for the screen layout (`screenStyle`, pushed down into `ScreenSpawn`); `AUTO` follows the configuration through `SwarmPlaneController.StyleForConfiguration`, and consumers read `ResolvedScreenStyle`. other components change the layout through `SetScreenStyle` (refused under `AUTO`), never by writing the field; `displayYawSmoothTime` is the screens' yaw low-pass.
- [screenSpawn.cs](Assets/Scripts/Interface/screenSpawn.cs) — per-drone feed quads with several layouts; `ShowFallbackFeeds(on, style)` is the fallback entry point (the passed style only substitutes for a configured `OFF`; any visible layout is kept). `OUTER_CIRCLE` places each screen at its own drone's yaw; `FORMATION_WALL` is the shared-heading equivalent (yaw aims the wall, in-plane rank separates the screens); `FORMATION_MAP` is the nadir counterpart of the wall (ranked and hung in the pilot's body-yaw frame, ahead at the top, each feed rolled so the imagery is map-aligned). Both grids are solved once per frame by `BuildFormationGridLayout`. Each `DroneScreenBinding` is a sim drone or a real feed (`feedIndex`), read through one set of accessors (`TryGetDisplayYawRad`, `TryGetSamplePosition`, `SampleYawDeg`, `IsFeedSuppressed`); the display yaw is low-passed once per frame (`StepDisplayYawFilters`); `Screens` is the list texture consumers must use. Also owns the FPV render throttle (`feedRenderHz`, default 30): the eye cameras are culled to these quads, so the FPV cameras are the whole render cost, and `StepFeedRenders` drives them manually on a staggered fixed-rate schedule — skipping slots already rendered by the capture, thinning screens out of view (`offViewFeedRenderHz`) and leveling over-budget frames (`levelFeedRenders`) — instead of leaving them `enabled`.
- [VrFramePacing.cs](Assets/Scripts/Interface/VrFramePacing.cs) — no scene object needed: vsync off, frame rate uncapped, `Time.maximumDeltaTime` 0.1 s so a hitch cannot burst into catch-up physics steps.
- [BodyYawCompass.cs](Assets/Scripts/Interface/BodyYawCompass.cs) — the faint arrow below the pilot pointing along the body yaw; added automatically to any scene with an Arena, on the feed-screen layer, no collider.
- [EyeTracking/EyeGazeTracker.cs](Assets/Scripts/EyeTracking/EyeGazeTracker.cs) — Quest Pro gaze through OVRPlugin as a read-only static API (per-eye and combined world rays, confidence-gated; disables itself without eye tracking), read by `ExperimentRecorder`'s gaze columns. [GazeDebugCursor.cs](Assets/Scripts/EyeTracking/GazeDebugCursor.cs) is its in-headset debug cursor (off by default).
- [csc.rsp](Assets/csc.rsp) — `-unsafe` for Assembly-CSharp, for the bridge's in-place readback (the Player setting is not picked up by an editor holding the project open).

## Python stitching pipeline

- [StitcherThreading.py](Assets/Scripts/ImageStitching/StitcherThreading.py) — orchestrator + 3 threads (block read, fast render, slow warp); `StitcherManager` holds the backends. Maps all three sections once at their constant sizes (named via `shm_name()`, which appends `STITCH_SHM_SUFFIX`) and never remaps; `_fatal` exits non-zero on an unmappable section, a geometry disagreement with the producer, or a stalled heartbeat. `first_thread` wakes the render only for a fresh block (`captureTime` advanced), floored at `RENDER_MIN_PERIOD`; the status line every 10 s reports Unity's frame rate from the heartbeat.
- [run_clock.py](Assets/Scripts/ImageStitching/run_clock.py) — the `[up H:MM:SS]` stamp every periodic console line shares.
- [StabStitcher.py](Assets/Scripts/ImageStitching/StabStitcher.py) — StabStitch++ backend: rolling 7-frame buffer with per-frame cached Spatial/Temporal net outputs (`_ingest`, admitted at `NET_FRAME_PERIOD`), SmoothNet per warp update at `WARP_PERIOD` (10 Hz), the window restarted for a new triplet (`_restart_video`), antialiased net input (`lr_antialias`), fusion modes, the panorama-quality estimate with its timed, asymmetric debounce (`QUALITY_HIDE_S` / `QUALITY_SHOW_S` + PSNR margin), and the wire-ready render (`WireReadyPanorama`: RGB, bottom-up, at the panorama size).
- [tools/stabstitch_selftest.py](Assets/Scripts/ImageStitching/tools/stabstitch_selftest.py) — GPU self-test for the StabStitch path: incremental cache vs legacy full-window warp, GPU vs cv2 preprocessing, wire render vs cv2 post-processing, the vendored edits vs a pristine copy rebuilt from `tools/stabstitch2_perf.patch`, a device-sync budget, and timings.
- [tools/stabstitch_bridge_bench.py](Assets/Scripts/ImageStitching/tools/stabstitch_bridge_bench.py) — times the whole STABSTITCH bridge end to end without Unity: a stand-in producer (metadata, posed blocks, heartbeat, panorama reads) on suffixed sections (`STITCH_SHM_SUFFIX`) with the real `StitcherThreading.py` as a subprocess; reports stitch/warp rates and panoramas delivered.
- [tools/stabstitch_flicker_replay.py](Assets/Scripts/ImageStitching/tools/stabstitch_flicker_replay.py) — `record` captures the three STABSTITCH slots from a playing Unity (read-only, never takes a block flag); `replay` runs a recording through `StabStitcher` on a simulated clock and scores panorama stability in panorama pixels (jitter, warp shape, the paper's roughness, new-video transients, `--switch` for a triplet change).
- [tools/stabstitch2_perf.patch](Assets/Scripts/ImageStitching/tools/stabstitch2_perf.patch) — the perf edits to the gitignored `StabStitch2_main` code (cached constants, `inv_ex`); re-apply from `Codes/` after re-downloading StabStitch2.
- [PlanarStitcher.py](Assets/Scripts/ImageStitching/PlanarStitcher.py) — pose-driven planar backend for the facade/nadir configurations: validates each block's pose (`pose_is_usable`), builds one exact homography per view from pose, warps and combines N views (winner-take-all by obliquity, or feather-blend), frames the canvas on Unity's centre drone (`Fixed` or `AutoFit` via `_footprint_bbox`; zoom/pan are view-only), derives the plane from the poses for `FormationRelative` (`_plane_from_formation`), and owns the projective/coverage/plane gates. `compute_warps` runs the two warp-thread estimators: the ACQUIRE/TRACK plane sweep (sampled in disparity, not metres) and the per-view pose refiner, logged by `_maybe_log_estimators`; their switches arrive live through `set_live_config`.
- [planar_geometry.py](Assets/Scripts/ImageStitching/planar_geometry.py) — pure-numpy geometry for the above: Unity→CV frame conversion, plane frame, `G`, footprints, Jacobian anisotropy. No Unity, torch or shared-memory dependency, so it is testable in isolation.
- [planar_bundle.py](Assets/Scripts/ImageStitching/planar_bundle.py) — plane-supported correspondences (ORB matches triangulated across view pairs, consensus taken in depth) giving the dominant surface's offset, its inliers and the on-plane seam residual. Used by the clip bench; not wired into the live stitcher.
- [tools/planar_selftest.py](Assets/Scripts/ImageStitching/tools/planar_selftest.py) — offline geometry + end-to-end render checks; cross-checks projection against an independent Unity-derived reference.
- [tools/check_wire_layout.py](Assets/Scripts/ImageStitching/tools/check_wire_layout.py) — parses `PyUniSharingFast.cs`, `StitcherThreading.py` and `ImageSharing.cs` and asserts their shared-memory layout constants agree — metadata offsets, block header, the panorama sequence shift, and the fixed section geometry (capacity, stride, section bytes) that all three must request identically; also checks the DJI_Swarm repo's feed header and the feed trailer's page-rounding bound when that repo is checked out alongside.
- [tools/planar_feed_bench.py](Assets/Scripts/ImageStitching/tools/planar_feed_bench.py) — synthetic drone feed for the real-drone `PLANAR` path: renders a facade from N virtual drones and writes real `DroneFeedSharedMemory` blocks, so Unity + the stitcher run unmodified with no aircraft. `--selftest` runs the same scene headless with no Unity at all.
- [tools/planar_clip_bench.py](Assets/Scripts/ImageStitching/tools/planar_clip_bench.py) — replays a recorded real-drone clip through `PLANAR` headless (no Unity, no shared memory) and scores the plane-supported seam residual in metres, with overlap PSNR beside it for comparison.
- [BaseStitcher.py](Assets/Scripts/ImageStitching/BaseStitcher.py) — the feature-matching base (SuperPoint + BF/FLANN) the older backends (`UDISStitcher`, `NISStitcher`, `REStitcher`) build on.

## Swarm testing offline (headless bench + replica)

All in `Assets/Scripts/swarm/Bench/`; [README.md](Assets/Scripts/swarm/Bench/README.md) is the manual. Run the Python with the `stitching` env.

- [run_bench.ps1](Assets/Scripts/swarm/Bench/run_bench.ps1) — the headless Unity bench: mirrors this working tree into a project copy on D: (the live editor holds the project), keeps its Library, deletes `ilpp.pid`, refuses a second Unity on the copy, runs batchmode with a timeout and one retry, and prints the report. `-CompileOnly` / `-SyncOnly`.
- [SwarmBenchRunner.cs](Assets/Scripts/swarm/Bench/SwarmBenchRunner.cs) — the runtime harness, inert unless `SWARM_BENCH_CONFIG` is set: disables sockets/sections/recorder/cameras, steers waypoint flights in world terms (hold waypoints too: a centring pilot at a goal, as the replica and citysim fly it), applies parameter sets as overrides on the scene's SwarmManager (snapshot + restore), forces the look-gap fill off without an injected pilot heading, overrides `VrFramePacing`'s `maximumDeltaTime`, builds a generated layout in ProceduralCityWorld (`layout`), sets the drone count (`droneCount`; a lone drone's heading is steered by the scripted pilot), and writes self-describing JSON lines plus per-flight trajectories (alive / hull / shown masks, x/z/yaw/y, waypoint, body yaw).
- [Editor/SwarmBenchLauncher.cs](Assets/Scripts/swarm/Bench/Editor/SwarmBenchLauncher.cs) — batchmode entry points: `Run` (opens the config's scene, enters play mode) and `CompileCheck`.
- [bench.py](Assets/Scripts/swarm/Bench/bench.py) — `scenarios` (generate a held-out set + spread steps for a city or a generated layout; `--goals` writes the density study's Tier C goal flights, on the street route or -- `--routing pilot` -- on citysim.routing's pilot paths for the swarm and the single drone), `config` (build one, validated against SwarmManager.cs; `--layout`, `--drones`, `--walkers`, `--record-all`), `report` (losses, contacts, clean %, speed, step t90/overshoot; reads the September result format too).
- [scenarios/](Assets/Scripts/swarm/Bench/scenarios) — flight sets: ScaledCityWorld's frozen from the September retune, DiamondCityWorld's generated (seed 1).
- [swarm_replica.py](Assets/Scripts/swarm/Bench/swarm_replica.py) — the 2D replica: `sim` (closed loop on a test's recorded pilot inputs, through each run's runtime city — a procedural run's own layout), `forces` (per-term closing-acceleration attribution at each recorded crash), `step` (spread step response), `validate` (the replica's gate: flies a bench run's recorded flights again and compares track, spacing, losses and contacts), `params`. `ContactSim` is the Unity-faithful loss model (footprint entry = contact with friction, isolation loss) that `validate` and the density study fly. Mirrors the C# force law as of `FORCE_LAW_COMMIT` and refuses once git shows it changed.
- [swarm_params.py](Assets/Scripts/swarm/Bench/swarm_params.py) — resolves SwarmManager and airframe values from the C# initialisers, scene YAML, `DroneReduced.prefab`, a test's `swarmParams` and a run's `<stem>_swarm.json`, recording where each came from.

## Environment / scenery

Scene builders first (each scene below is generated, so rebuild it rather than hand-editing it), then the runtime city components and the city tools.

- [Editor/DiamondCityBuilder.cs](Assets/Scripts/Environment/Editor/DiamondCityBuilder.cs) — `Tools/Swarm/Build diamond city`: `DiamondCityWorld`, ScaledCityWorld's 48 tiles re-laid on an 8 × 8 grid (moved by kerb, scenery and all) with four diamond superblocks across the straight north–south corridors. The layout is data (`Layout`); each diamond is drafted once from four tiles and saved as a prefab, and later builds place the prefab as it stands, so restyling survives. Diamond kerbs/blocks are renamed so the city tools don't take them for tiles; `CityRowOffsetter` is removed; the spawn road is lengthened by copying its outer segment.
- [Editor/DiamondParkBuilder.cs](Assets/Scripts/Environment/Editor/DiamondParkBuilder.cs) — `Tools/Swarm/Build diamond parks`: every diamond is its own root holding `Base` (a nested `Diamond_Base.prefab`: the lawn, fountain and street shells, made once from Diamond_B), `Plazas` (two per diamond, as Diamond_B's were first made by hand: a plain footpath exactly a city block's size at the 0.8 block scale — so a goal replacing it comes out the same size — with a screen of copied 50-unit buildings across the north–south street it blocks, scattered over the plaza from a per-plaza seed rather than packed into a wall — at least 3 m apart and together covering at least 60% of the street's open width, verges included (80% preferred, as on Diamond_B's hand-made plazas), the build refusing a plaza that cannot; each carries a `DiamondPlaza`; kept once drafted, so redraft with `Tools/Swarm/Build diamond parks, redrafting plazas`, or `DIAMOND_REDRAFT_PLAZAS=1` in batchmode; its furniture under `Props` — park lamps round the edge, benches facing the lawn with bins, hedge beds, planters in the corners and off each building's corners, copied from MC_Patch_16's park block on Default — is rebuilt every run from where the buildings stand, skipping any spot within 1 m of one, and leaves with the plaza when a goal replaces it) and `Park`, rebuilt each run from a per-diamond `DiamondSpec` (tip buildings, which arms get double rows vs groves, tree model per arrangement, seed) so the four are distinct. Nested rather than Prefab Variants because a variant's new root would orphan DiamondCityWorld's placement overrides. The park is measured from the lawn and fountain: four `Assets/Tree9` models in a ring, avenues, double rows and groves, and a 50-unit ScaledCity building on a generated footpath at each tip; then its furniture under `Park/Props`, laid out by the tree arrangements and placed after them so the planting never moves for it — a round of plaza paving about the fountain (`Generated/Diamond_Fountain_Paving`) with benches facing the water, bins, lamps and planters at the ways in; lamp pairs and bench pairs in alternate gaps down each avenue; benches with bins under the double rows and along the fronts of the groves; hand edits under `Park` are lost on a re-run. Also gives the base's planes `DiamondParkGrass.mat` (the terrain's `BaseLayer` at its tile size), keeps them off `Obstacle` (a 76-unit plane is a ~54-unit avoidance cylinder), and renames plazas' `Carbs_`/`MC_Patch` nodes, since a kerb under the diamonds' root makes `CityTiles.FindCity` fail.
- [Editor/PracticeWorldBuilder.cs](Assets/Scripts/Environment/Editor/PracticeWorldBuilder.cs) — `Tools/Swarm/Build practice world`: regenerates `PracticeWorld.unity`, the participants' training scene, as ScaledCityWorld with every tile but one (`MC_Patch_14`, moved down ParkRoad from the spawn) and one finished goal patch behind it, the experiment and city-tuning components removed, plus the four walker prefabs — cap, bucket, cowboy, no hat — standing under two-sided signs naming the hat. Copying rather than authoring is what keeps the flight experience identical, because the gains, ceiling, spawn, input, display and rig all live on scene objects: rebuild after changing ScaledCityWorld, and expect hand edits to the practice scene to be lost when you do. The walkers stand because no `WalkerPatrol` drives them; their Animator is switched from the walk clip to the pack's `HumanM@Idles` loop, with root motion off, since the walk clip would have them walking on the spot and no Animator at all is a T-pose.
- [Editor/ProceduralCityWorldBuilder.cs](Assets/Scripts/Environment/Editor/ProceduralCityWorldBuilder.cs) — `Tools/Swarm/Build procedural city world` (DiamondCityWorld copied, its city, diamonds and city tuners stripped, a `ProceduralCity` root added) and `Tools/Swarm/Build procedural city from layout…`, which builds a trial layout in edit mode and bakes it, so saving after a preview is safe.
- [Editor/VoronoiCityWorldBuilder.cs](Assets/Scripts/Environment/Editor/VoronoiCityWorldBuilder.cs) — `Tools/Swarm/Build Voronoi city world`: `VoronoiCityWorld.unity`, DiamondCityWorld's own building mix on the density study's Voronoi streets (a `citygen mixcity` layout, `layouts/VoronoiCity__<id>.json`), on `ProceduralCityWorldBuilder`'s scene with the city baked in and textured streets. Batch: `-executeMethod VoronoiCityWorldBuilder.Run` (`CITY_LAYOUT` overrides the layout); `Rebake` bakes `CITY_LAYOUT` into the scene as it stands.
- [Editor/VoronoiCityWindow.cs](Assets/Scripts/Environment/Editor/VoronoiCityWindow.cs) — `Tools/Swarm/Voronoi city…`: tunes VoronoiCityWorld's coverage, seed, block spacing, street width and facade gap by running `mixcity` in the `stitching` env and rebaking the open scene (each generation writes its own layout file), reports when the blocks jam or OlfatiSaber's 64-collider query would be overrun, and its *Layouts* list picks which of S3's coverage levels (0.0227 / 0.04 / 0.06 / 0.10) Play flies.
- [ProceduralCityBuilder.cs](Assets/Scripts/Environment/ProceduralCityBuilder.cs) — on its own `ProceduralCity` root (never `gameManager`): builds a generated layout (`layoutPath`, overridden by `CITY_LAYOUT`) from the `BuildingCatalogue` — buildings placed by collider centre on `Obstacle`, street meshes with no colliders (`StreetStyle.Flat`, the study's look, or `Textured` road via `StreetSurface`), the swarm spawn from the layout, each goal from `ProceduralGoalRoot.prefab` (centre occluder + ring buildings with `WalkerPatrol`s, activated after its children so `GoalSpecialWalker` sees them). `Bake` saves the city (never the goal roots) into the scene; at Play `Adopt` keeps a bake only while it is the layout to build and every building still stands on its box, and otherwise rebuilds from the file. `PlacedGoals` is in layout order, which the recorder uses.
- [StreetSurface.cs](Assets/Scripts/Environment/StreetSurface.cs) — a layout's streets as road: one mesh, lane-marked stretches (ParkRoad's asphalt) on submesh 0 and plain junctions + zebra crossings on submesh 1; each street stops at the setback where its kerb meets its neighbour's, and Voronoi edges too short to draw are merged into one junction.
- [ProceduralGoal.cs](Assets/Scripts/Environment/ProceduralGoal.cs) — marker on a procedural goal root: its index in the layout, r_g, w_c, c_g, the patch and cleared radii, and the centre/ring box ids; an `IGoalZone` whose zone is a disc.
- [CityLayoutInfo.cs](Assets/Scripts/Environment/CityLayoutInfo.cs) — the built layout's record (id, path, seed, design, size, p, s, f, coverage, scene, generator version) for `ExperimentRecorder`'s session JSON.
- [BuildingCatalogue.cs](Assets/Scripts/Environment/BuildingCatalogue.cs) — the ScriptableObject `ProceduralCityBuilder` instantiates from: one entry per ScaledCity building design (source prefab object, collider size/centre, the z-scale for 50 m), and the study design.
- [Editor/BuildingCatalogueExport.cs](Assets/Scripts/Environment/Editor/BuildingCatalogueExport.cs) — `Tools/Swarm/Export building catalogue`: scans the 48 ScaledCity patch prefabs, groups buildings by design (the `ObstacleLayerAuditor.Family` rule), writes `BuildingCatalogue.asset` and `Experiment/building_catalogue.json`.
- [GoalPatchReplacer.cs](Assets/Scripts/Environment/GoalPatchReplacer.cs) — at play-mode Start, randomly swaps `n` of the `MC_Patch_*` tiles under `City_Pack_01` for a `goal_patch` prefab (non-adjacent placement). The goal is laid over the tile's *block*, located by its kerb, not copied from the tile's transform — `MC_Patch_32`'s transform is ~318 u from its block. Y pinned to 0. Hands the replaced tile's tied `Scenery`, `Street` and `Verge` children to the goal. Diamond plazas (`DiamondPlaza`) are candidates too (`includeDiamondPlazas`): their goal still goes under `City_Pack_01` (so `FindCity` and the tuner's 0.8 scaling work), over the plaza's centre at its raised ground, with its road plate hidden; its verge trees then stand on the park lawn round it; adjacency spacing comes from the tiles alone. It sits on `gameManager`, which `SwarmManager` moves to DontDestroyOnLoad, so never test `gameObject.scene` against city objects here; replanting every goal's verge (`PlantGoalVerges`) failed for exactly that reason until 2026-09-30.
- [GoalSession.cs](Assets/Scripts/Environment/GoalSession.cs) — the session's goal seed and where it came from (a layout, a replayed session, or drawn): `GoalPatchReplacer`'s goal choice, `GoalSpecialWalker`'s hat deal and `WalkerPatrol`'s target index all draw from it, and `ExperimentRecorder` logs it, so Replay mode reproduces all three.
- [GoalZone.cs](Assets/Scripts/Environment/GoalZone.cs) — `IGoalZone`: a goal's zone and geometry (disc of radius r_g for a procedural goal, the tile square for a patch goal; occluder width, clearance) behind one interface, for the recorder's zone test and auto-scored identify.
- [GoalSpecialWalker.cs](Assets/Scripts/Environment/GoalSpecialWalker.cs) — guarantees exactly one visually-distinct pedestrian (`CapWalker` / `CowboyWalker` / `BucketWalker`, listed by name in `DefaultPrefabNames` because their only shared token is the `Walker` suffix, which `SimpleWalker` shares too) per goal patch. A patch holds several `WalkerPatrol` components each spawning its own batch, so "one per goal" cannot be decided inside a single patrol; this sits on the patch root and picks one patrol at random in `Awake`, before any patrol's `Start` spawns walkers. **Which** hat a goal gets is dealt from a shuffled deck shared by every patch (static, reset on entering play), because each patch decides alone and independent random picks would collide; a new round never opens on the hat the last one closed with. The hat's name rides on the `SpecialWalker` marker — on the prefab, so renaming or reordering the list cannot relabel a session's data — and `ExperimentRecorder` writes it per goal (`walkers.csv` `hat` column, and `hat` in the session JSON's `goals`). `ModifiedWalker`'s hat hangs off the model's **head bone** (`B-head`), not off the model root: the walk clip carries the head 4–6 cm down and 7–9 cm forward of the bind pose for the whole stride, so a hat on the root floats above and behind the head on every step. Its 1.3 scale is load-bearing too — the hat's crown is 16.2 cm across unscaled, narrower than this character's 19.8 cm skull.
- [Interface/WalkerPatrol.cs](Assets/Scripts/Interface/WalkerPatrol.cs) — spawns and moves a goal's walkers on a rounded rectangle about its collider (or the original circle), under a `SpawnedContentRoot` container. [Interface/SpecialWalker.cs](Assets/Scripts/Interface/SpecialWalker.cs) is the marker on the one hat-wearing target, carrying its hat id.
- [DiamondPlaza.cs](Assets/Scripts/Environment/DiamondPlaza.cs) — marks a plaza in a diamond's park: a block-sized footpath with buildings screening the street, no road ring or verge. Plazas are not tiles (a `Carbs_` kerb under the diamonds' root breaks `CityTiles.FindCity`), so this component is how `GoalPatchReplacer` and `CityObstacleExport` find them. Its ground stands 0.1 up so a goal replacing it clears the park's 4 cm lawn with its interior streets.
- [CityTiles.cs](Assets/Scripts/Environment/CityTiles.cs) — what the city tools share about the pack's grid: pitch, the kerb-line half span (38.1), finding the city and its tiles by kerb, the square-footprint owner rule, and the three tied-scenery containers with the share of the block's shrink each follows (`Scenery` 1, `Street` 0, `Verge` ½).
- [Editor/CitySceneryParenter.cs](Assets/Scripts/Environment/Editor/CitySceneryParenter.cs) — `Tools/Swarm/Report city scenery ties` and `Tools/Swarm/Tie city scenery to tiles`. The pack hangs street medians, a garden and 48 duplicate road plates off the city root, so moving a tile leaves them behind. This divides the street-width tuning back out to find each object's authored position, puts medians (beyond the kerb line) under `Street` at that position — the tuning had pulled them onto a verge — and everything else under `Scenery`, splitting straddling groups into per-tile copies. Unpacks the city prefab instance in the scene (outermost layer only) because Unity will not reparent inside an instance. Re-runnable; one undo step.
- [StreetWidthTuner.cs](Assets/Scripts/Environment/StreetWidthTuner.cs) — widens the streets between city tiles by shrinking each tile's block content about its own kerb pivot while leaving the `Road_Structure` plate and the 90.83 grid pitch alone. That plate is a road *ring* from the tile edge in to the kerb line, empty inside, so the widened strip shows whatever is under the city — a grass Terrain, i.e. a verge — and the carriageway itself does not widen. Buildings and props are moved, never resized. Tied scenery follows its container's share of the shrink, so medians stay mid-street. Street width is `90.8304 - 76.2 x blockScale`. Edit-mode only, for the same static-batching reason as `BuildingWidthTuner` — except `MatchNewPatches`, which runs on the first `Update` of a tuned play session to size the goal patches `GoalPatchReplacer` spawns, and so is the one path that meets runtime-spawned objects. It skips [SpawnedContentRoot](Assets/Scripts/Environment/SpawnedContentRoot.cs) subtrees for that reason.
- [SpawnedContentRoot.cs](Assets/Scripts/Environment/SpawnedContentRoot.cs) — marker saying "this subtree was spawned during play; city tools leave it alone", added by `WalkerPatrol` to its walker container. The tuners take a tile's block content to be *every Renderer under the tile*, which is right for an authored prop (one object, one renderer) and wrong for a composite: a walker's renderers are children of the object the patrol drives, so scaling them about the kerb pulls the walker apart instead of moving it — silently for the skinned body, which renders from its bones and ignores its own transform, and by metres for the hat, which is how it was found.
- [VergeTreePlanter.cs](Assets/Scripts/Environment/VergeTreePlanter.cs) — plants trees (default `MC_Tree`) down the middle of that grass verge on a seeded fraction, a list, or all tiles, under each tile's `Verge` container; skips spots near existing props and interior street mouths. Deterministic by seed and tile name, and scriptable (`Plant()`, `Plant(tiles)`, `Clear()`, settings as properties).
- [CityRowOffsetter.cs](Assets/Scripts/Environment/CityRowOffsetter.cs) — staggers alternate rows of tiles by a fraction of a tile (optionally centred), live in edit mode, to break up straight street corridors. Moves tile roots only, so it refuses while any scenery is still untied; `Restore authored grid` undoes it exactly.
- [Editor/BuildingUvBaker.cs](Assets/Scripts/Environment/Editor/BuildingUvBaker.cs) — one-off editor bake that removes the ScaledCity buildings' texture stretching. Their non-uniform `localScale` (0.25 wide, height normalised to 50 u) distorts facade texels by a median 7.8x, and the buildings share two UV *atlases*, so neither `_MainTex_ST` nor scaling UVs outward is safe — both land on a neighbouring building's or a prop's slice of the sheet. Instead it contracts each UV chart along whichever direction is over-dense, about the chart's own centroid: never outward, so nothing can leave its own region, and the pack meshes that deliberately rely on Repeat wrap keep working. Writes mesh copies into `ScaledCityBuildingMeshes.asset` and re-points the 220 MeshFilters; [BuildingUvBakeManifest.cs](Assets/Scripts/Environment/BuildingUvBakeManifest.cs) records the originals so `Tools/City/Restore original building meshes` reverses it.
- [BuildingWidthTuner.cs](Assets/Scripts/Environment/BuildingWidthTuner.cs) — scales the horizontal footprint of the four building families in any Modular City Pack scene, height untouched. `widthScale` is *relative* (1 = leave alone), because ScaledCityWorld bakes 0.25 into its prefabs and CityWorld bakes 1. Edit-mode only: the pack marks buildings `Batching Static`, so a runtime change would move colliders without moving the visible mesh — `ApplyWidth` refuses rather than producing invisible walls. Runtime-spawned geometry (goal patches) is matched on the first frame.
- [TerrainHeightSampler.cs](Assets/Scripts/Environment/TerrainHeightSampler.cs) — ground height under a world position, off the scene's Unity Terrains, for the swarm's altitude ceiling (`SwarmManager.maxHeightAboveTerrain`). Caches the terrain list because `Terrain.activeTerrains` allocates an array per access and the ceiling asks per drone per physics tick; the sample itself is a heightmap lookup and is free. Rebuilt only on scene load/unload or a destroyed terrain — terrain is static scenery here. Past the edge of the terrain the nearest tile answers, clamped into its bounds, so flying off the map is not a way out from under the ceiling; a scene with no Terrain at all returns false and gets no ceiling.
- [Editor/ObstacleLayerAuditor.cs](Assets/Scripts/Environment/Editor/ObstacleLayerAuditor.cs) — `Tools/Swarm/Audit obstacle layer` and `Tools/Swarm/Restrict obstacle layer to buildings`. Reports and repairs which colliders `OlfatiSaber` will treat as obstacles, the membership rule being solely "collider on layer `Obstacle`". Exists because CityWorld and CrowdWorld put the whole city on that layer, and a flat 90.83 x 90.83 `Road_Structure` plate becomes a ~64-unit-radius cylinder under the bounds-circumradius model. Keep its building-family list in step with `BuildingWidthTuner`'s.
